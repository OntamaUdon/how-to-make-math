# 第2章 Claudeにできること

## 最初の疑問：Claude はどこで作業しているのか

第1章の最初に、あなたはこう言われました。「**私からはアップロードできません**」。

なぜでしょう。Claude は賢いのに、あなたのPCのフォルダに手が届かない。
この理由が分かると、Claude と GitHub の関係が一気に見えてきます。

Claude Code（ブラウザやアプリから使うもの）は、**あなたのPCではなく、クラウド上の別のマシン**で動いています。
そのマシンは使い捨てで、作業のたびに用意されます。

作業の流れを絵にすると、こうなります。

```text
あなたのPC ──push──▶ GitHub ◀──clone/push── Claude のクラウドマシン
 (ローカル)          (みんなの置き場)           (使い捨ての作業場)
```

Claude は GitHub からリポジトリを**まるごとコピー**（<Term>clone</Term>）して作業し、結果を GitHub に push で返します。
あなたのPCとは直接つながっていません。**GitHub が、あなたと Claude の共通の机**になっているのです。

> だから、GitHub にコードを置く意味は「バックアップ」だけではありません。
> **Claude と作業するための前提条件**でもあります。

<Statement kind="remark" title="クラウドの作業場は使い捨て">
Claude のマシンは、作業が終わると片付けられます。push していない変更は消えます。
だから Claude は、作業の最後にコミットして push します。「GitHub に載った＝残った」です。
</Statement>

## このサイトで頼めること

では、GitHub に載せたこのサイトで、実際に何を頼めるでしょうか。
いまのサイトの構造に合わせて、具体例を挙げます。

**文章まわり**
- 「線形代数の第5章の説明を、もっと初心者向けに書き直して」
- 「群論の第3章に、例を2つ足して」
- 「全章で、同じ記号の書き方が揺れていないか調べて」

**部品まわり**
- 「確率論の章に、サイコロを振るインタラクティブ図を作って」（`src/components/interactive` に新しい部品を足す）
- 「この図の色が見づらいので直して」

**調べもの・点検**
- 「ビルドが通らない。原因を探して」
- 「`navigation.ts` の隠し部の仕組みを説明して」
- 「リンク切れがないか確認して」

**GitHub の操作そのもの**
- ブランチを作る、コミットする、push する
- Pull Request（第3章）を作る、レビューのコメントに返事して直す
- Issue（作業メモ）を読む・書く

## 「頼み方」で結果が変わる

Claude は、書いてあることを書いてあるとおりにやります。察してくれる範囲には限りがあります。

| 頼み方 | 何が起きやすいか |
| :-- | :-- |
| 「サイトを良くして」 | 何を良くするか Claude が決めてしまい、望まない変更が混ざる |
| 「群論の3章の冒頭を、定義から始めず、たとえ話から始めるように直して」 | 範囲と方針が決まっているので、狙いどおりになりやすい |

コツは3つです。**どのファイルか、何をどうしたいか、何は変えないでほしいか**。
この3つが入っていれば、たいてい意図に近づきます。

## できないこと・気をつけること

正直に書きます。Claude には限界があり、そこを知っているかどうかが、安全に使えるかどうかを分けます。

**1. あなたのPCのファイルは見えない**
さきほどのとおりです。GitHub に載っているものだけが、Claude の世界のすべてです。

**2. 間違えることがある**
文章も、コードも、数式も、です。とくに数学のサイトでは、**定理の主張や証明の正しさは、必ず人の目で確認**してください。
もっともらしいのに間違っている、が一番厄介です。

**3. 「動くかどうか」は試さないと分からない**
このサイトは、ビルドに大きなメモリ（8GB の上限指定）を使います。Claude のクラウドマシンでビルドが通るかは、実際にやってみるまで分かりません。
通らなかった場合は、そう報告されるはずです。「通ったはず」は信用しないでください。

**4. 勝手に main を書き換えない（ように設定されている）**
Claude は、指定された作業ブランチだけに push します。そして Pull Request は、**頼まれたときだけ**作ります。
これは安全装置です。次の章は、この安全装置の使い方の話です。

## 考え方：Claude は「手の速い共同執筆者」

ここまでをまとめると、Claude との付き合い方の型が見えてきます。

- **Claude に任せるもの**：下書き、機械的な修正、調査、点検、面倒な繰り返し作業
- **あなたが持つもの**：何を作りたいかの決定、内容の正しさの最終確認、main に取り込むかどうかの判断

「何を作るか」と「取り込んでいいか」を人が握り、「手を動かす部分」を Claude が速く進める。この分担が、いちばん事故が少なく、いちばん速いやり方です。

## ありがちな勘違い

**勘違い1：「Claude に頼めば、サイトがすぐ更新される」**
Claude が作業しても、変更が載るのはまず**作業ブランチ**です。main に入れる（＝本体を変える）のは、次章の手順を踏んだあとです。

**勘違い2：「Claude は会話を全部覚えている」**
作業場は使い捨てです。大事な決定は、コミットメッセージや説明文として**リポジトリに残す**ほうが確実です。

**勘違い3：「Claude の変更は、読まなくていい」**
読んでください。読んだうえで取り込む、が基本です。

## この章のまとめ

- Claude はクラウド上の別マシンで動き、GitHub を経由してあなたと作業する。
- 文章・部品・調査・GitHub 操作を頼める。頼み方は「どこを、どうしたい、何は変えない」。
- 見えない物がある、間違える、動作は試さないと分からない。
- 役割分担：決めるのと最終確認は人、手を動かすのは Claude。

最後の章では、Claude が作った変更を**安全に確認して取り込む手順**を見ます。
