# 第2章 ノードとシーン

## この章がこの部で一番大事です

Godot には、ほかのエンジンにない特徴的な考え方があります。それが **ノードとシーン** です。

ここを飲み込むと、あとは全部「その応用」になります。
逆にここを飛ばすと、コードは書けるのに構成が破綻して、
「なんか動いてるけど自分でも何がどうなってるか分からない」ゲームができあがります。

急がずに行きましょう。難しい話ではありません。**レゴブロック**の話です。

## ノード＝ひとつの仕事をする部品

<Statement kind="definition" title="ノード（Node）">
Godot でゲームを構成する最小の部品。**ひとつのノードは、ひとつの仕事だけ**をする。
絵を出すノード、音を鳴らすノード、時間を計るノード、当たり判定を持つノード……というふうに、
役割ごとに専用のノードが用意されている。
</Statement>

たとえば「プレイヤーキャラ」は、Godot では1個の部品ではありません。

- `CharacterBody2D` … 移動と衝突を担当する
- `Sprite2D` … 絵を表示する
- `CollisionShape2D` … 当たり判定の形を持つ
- `AudioStreamPlayer2D` … 効果音を鳴らす

この4つを**組み合わせて**プレイヤーにします。
「全部入りのプレイヤーノード」は存在しません。単機能の部品を積むのが Godot 流です。

<Statement kind="remark" title="ノードの種類は数百ある。覚えなくていい">
公式にあるノードは 200 種類以上あります。全部覚える人はいません。
**＋ボタンを押して検索する**のが正しい使い方です。
「音を鳴らしたい」なら `Audio` と打つ。「文字を出したい」なら `Label` と打つ。
この部では実際に使う20個ほどだけを、出てくるたびに説明します。
</Statement>

### アイコンの色で種類がわかる

ノードを追加するウィンドウで、アイコンの色を見てください。

| 色 | 種類 | 例 |
| --- | --- | --- |
| 青 | 2Dの世界のもの | `Node2D` `Sprite2D` `Area2D` |
| 赤 | 3Dの世界のもの | `Node3D` `MeshInstance3D` |
| 緑 | UI（画面に貼り付くもの） | `Control` `Label` `Button` |
| 灰 | どの世界にも属さないもの | `Node` `Timer` `HTTPRequest` |

**青と緑を混ぜると事故ります。** 2Dの世界に置きたいのに緑のノードを使うと、
位置の指定方法が違うので思ったところに出ません。この部では
「ゲーム内のもの＝青」「スコア表示やボタン＝緑」と使い分けます。

## ツリー＝親子に組む

ノードは**木の形（ツリー）**に組み立てます。あるノードの下に別のノードをぶら下げる。
上のものを<Term>親</Term>、下のものを<Term>子</Term>と呼びます。

```text
Player            ← 親（CharacterBody2D）
├── Sprite2D      ← 子
├── CollisionShape2D
└── Camera2D
```

親子にすると、**3つのこと**が自動的に起こります。これが親子にする理由のすべてです。

<Statement kind="definition" title="親子にすると起きる3つのこと">

1. **位置が親基準になる。** 子の位置 `(10, 0)` は「親から右に10」の意味になる。
   親が動けば子もついていく。回転や拡大縮小も引き継ぐ。
2. **親を消すと子も消える。** 敵を消すとき、その子の当たり判定や絵も一緒に片付く。
3. **上に書いたものから先に描かれる。** つまり**下にあるものほど手前**に表示される。

</Statement>

3つ目は最初つまずきやすいので強調しておきます。
シーンドックでノードを上下にドラッグすると、**重なりの順番が変わります**。
「キャラの後ろに背景を出したい」なら背景を上に、キャラを下に置く。それだけです。

## シーン＝ツリーを保存したもの

さて、組み上げたツリーは保存できます。それが<Term>シーン</Term>（`.tscn` ファイル）です。

<Statement kind="definition" title="シーン（Scene）">
ノードのツリーをひとかたまりにして、ファイルに保存したもの。拡張子は `.tscn`。
「ゲームの画面」だけでなく、「プレイヤー1体」「弾1発」「ボタン1個」もシーンにする。
</Statement>

ここで多くの人が引っかかるので、はっきり書きます。

> **Godot の「シーン」は、映画の場面という意味ではありません。**
> 「部品のかたまり」くらいの意味です。タイトル画面もシーンだし、
> 敵キャラ1体もシーンです。大きさは関係ありません。

### シーンは部品として使い回せる

シーンの真価はここです。作ったシーンは、**別のシーンの中に部品として置けます**。
これを<Term>インスタンス化</Term>（instantiate）と言います。

```text
Main.tscn                 ← ゲーム本編のシーン
├── Background
├── Player.tscn ●          ← Player シーンをまるごと1つの部品として配置
├── Enemy.tscn ●
├── Enemy.tscn ●          ← 同じシーンを何個でも置ける
└── HUD.tscn ●
```

`Enemy.tscn` を修正すると、**置いてある3体すべてに反映されます。**
敵の見た目を変えたければ `Enemy.tscn` を1回直すだけ。これが使い回しの威力です。

<Statement kind="example" title="やってみる：シーンを部品として置く">

1. 新しいシーンを作る（**シーン → 新規シーン**）。ルートに `Node2D` を選ぶ。
2. 子に `Sprite2D` を追加。インスペクタの `Texture` に、
   ファイルシステムから `icon.svg` をドラッグして入れる。
3. `Ctrl+S` で `player.tscn` として保存。
4. `main.tscn` を開く。**シーンドックの鎖のアイコン（子シーンをインスタンス化）** を押し、
   `player.tscn` を選ぶ。または、ファイルシステムから `player.tscn` を
   ビューポートに**ドラッグ＆ドロップ**してもよい。
5. `Ctrl+D` で複製して、位置をずらす。ロゴが2つ並ぶ。
6. `player.tscn` を開いて `Sprite2D` の `Modulate`（色）を赤にして保存。
   `main.tscn` に戻ると、**両方とも赤**になっている。

</Statement>

置いたインスタンスは、シーンドックで**フィルムのアイコン**が付いています。
中身を展開したいときは、そのアイコンを右クリックして「子を編集可能にする」。
ただし基本は**展開せずに使う**のがきれいな作り方です。

### インスタンスごとの上書き

置いたインスタンスの位置や色は、**その場所だけ変える**ことができます。
変更した項目には、インスペクタに**戻し矢印**が付きます。押せば元のシーンの値に戻ります。

つまり「基本は共通、この個体だけ少し違う」が自然に書けます。
敵Aだけ速い、敵Bだけ大きい、といった調整はこれでやります。

## ルートノードの選び方

新しいシーンを作るとき、**一番上のノードに何を選ぶか**は毎回悩みます。指針を出します。

| 作りたいもの | ルートに選ぶノード |
| --- | --- |
| ゲーム本編の画面全体 | `Node2D`（または何も持たない `Node`） |
| 操作するキャラ | `CharacterBody2D` |
| 物理で転がるもの | `RigidBody2D` |
| 触れたことだけ検知したいもの（アイテム・弾） | `Area2D` |
| 動かない地形・壁 | `StaticBody2D` |
| スコア表示・ボタンなどのUI | `Control` |
| 見た目だけの飾り | `Node2D` または `Sprite2D` |

迷ったら `Node2D` にしておけば、あとから右クリック → **型を変更** で変えられます。
（詰まったら変えればいい、と知っておくだけで手が動きます。）

## 実行中のツリー＝SceneTree

ここまでは「ファイルとしてのシーン」の話でした。
ゲームを起動すると、メインシーンが読み込まれて**ひとつの大きなツリー**が組み上がります。
これを <Term>SceneTree</Term> と呼びます。

```text
root (Window)              ← Godot が自動で用意する一番上
└── Main                    ← あなたのメインシーン
    ├── Player
    │   ├── Sprite2D
    │   └── CollisionShape2D
    └── Enemy
```

コードから `get_tree()` と書くと、この SceneTree 全体に触れます。
ゲームを止める、シーンを切り替える、全員に号令をかける——といった
「ゲーム全体に関わること」はここ経由で行います（第6章で使います）。

## ノードから別のノードを指す

スクリプトから「自分の子の Sprite2D」を触りたい場面は毎回あります。書き方は3つ。

```gdscript
# ① $ を使う（一番よく使う）
$Sprite2D.modulate = Color.RED
$CollisionShape2D/Marker2D.position = Vector2(0, 0)   # 孫は / でつなぐ

# ② 名前に空白や記号が入るときは $"..." と書く
$"Enemy Spawner".start()

# ③ get_node() は $ と同じ意味。文字列を組み立てたいときに使う
get_node("Sprite2D").modulate = Color.RED
```

`$` は「このノードから見た相対パス」です。フォルダのパスと同じ感覚で、
`..` で親をたどることもできます（が、これは壊れやすいので避けます。理由は後述）。

### `%` ユニーク名 — 引っ越しに強い書き方

`$` はパスなので、**ノードの位置を動かすと壊れます**。
深いところにあるノードを指すときは、こちらを使いましょう。

シーンドックでノードを右クリック → **「シーンのユニークな名前としてアクセス」** にチェック。
すると名前の横に `%` が付き、シーン内のどこからでもこう書けます。

```gdscript
%ScoreLabel.text = "100"     # 階層が何段深くても、どこに移動しても届く
```

UI のように階層が深くなりがちなものは、最初からこれにしておくと事故が減ります。

## ノードの一生（ライフサイクル）

スクリプトを書くとき、「**いつ**呼ばれるか」を知っている必要があります。
Godot があなたのノードに対して自動で呼んでくれる関数がいくつかあります。

<Statement kind="definition" title="よく使う4つのタイミング">

| 関数 | いつ呼ばれるか | 何に使うか |
| --- | --- | --- |
| `_ready()` | そのノードと子が全部そろった直後に**1回だけ** | 初期化。変数の準備、初期位置 |
| `_process(delta)` | **毎フレーム**（できるだけ速く、可変） | 見た目の更新、UI、入力の読み取り |
| `_physics_process(delta)` | **一定間隔**（既定で毎秒60回、固定） | 移動、当たり判定に関わる処理 |
| `_input(event)` | 入力が起きたときだけ | キー押下やクリックへの反応 |

</Statement>

`_ready()` の「子が全部そろった**あと**」という点が重要です。
だから `_ready()` の中では `$Sprite2D` が安全に使えます。
逆に、変数の宣言時に `$Sprite2D` を書くとまだ存在しなくてエラーになります。
そのための仕組みが `@onready` です（第3章で詳しく）。

```gdscript
extends Node2D

@onready var sprite: Sprite2D = $Sprite2D   # _ready() の直前に代入される

func _ready() -> void:
	print("準備完了")
	sprite.modulate = Color.AQUA
```

### ノードを消す

```gdscript
queue_free()        # 自分を「このフレームの終わりに」安全に消す
enemy.queue_free()  # 相手を消す
```

`free()` という即座に消す命令もありますが、**使わないでください。**
処理の途中で消えると、その後の行でクラッシュします。`queue_free()` が安全です。

## ノードを増やす・減らす（コードから）

敵や弾は、あらかじめ置いておくのではなく**その場で作ります**。

```gdscript
extends Node2D

# シーンファイルをあらかじめ読み込んでおく
const ENEMY_SCENE := preload("res://scenes/enemy.tscn")

func spawn_enemy() -> void:
	var enemy := ENEMY_SCENE.instantiate()   # シーンから実体を1つ作る
	enemy.position = Vector2(100, 50)
	add_child(enemy)                          # ツリーに加えて初めて画面に出る
```

3行の意味を押さえてください。

1. `instantiate()` … 設計図（シーン）から実物を1個作る。**まだ画面には出ない。**
2. `position = ...` … 出す場所を決める。
3. `add_child(...)` … ツリーに加える。**この瞬間に画面に現れ、`_ready()` が呼ばれる。**

<Statement kind="remark" title="Godot 3 との違い">
Godot 3 では `instance()` でした。Godot 4 で `instantiate()` に変わっています。
ネットの記事で `instance()` が出てきたら、それは古い記事です。
</Statement>

## グループ＝ノードにタグを付ける

「画面上の敵を全部消したい」「弾に当たったのが敵かどうか判定したい」。
そういうときに使うのが<Term>グループ</Term>です。ノードに付ける名札だと思ってください。

エディタなら、ノードを選んで右のドックの **「グループ」タブ** で追加します。
コードならこう。

```gdscript
func _ready() -> void:
	add_to_group("enemies")
```

使い方はこうなります。

```gdscript
# 全員に号令をかける（enemies グループ全員の die() を呼ぶ）
get_tree().call_group("enemies", "die")

# 相手が敵かどうか調べる
if body.is_in_group("enemies"):
	take_damage()
```

「相手のクラス名を調べる」より、グループで判定するほうが壊れにくく、読みやすくなります。

## 設計の指針：どこまでを1シーンにするか

慣れないうちに一番迷うところなので、実用的なルールを置いておきます。

<Statement kind="remark" title="シーンを分ける目安">

- **2回以上出てくるものは、必ずシーンにする**（敵、弾、コイン、ボタン）
- **1個しかなくても、中身が5ノードを超えたら分ける**（プレイヤー、HUD）
- **画面まるごと（タイトル、本編、リザルト）は必ず別シーン**
- 迷ったら**分ける**。あとで統合するほうが、あとで分けるより10倍楽です。

</Statement>

そして、**親子を越えて相手を直接いじらない**こと。

```gdscript
# 悪い例：親の、そのまた親の、UI の…と辿る。構成を変えた瞬間に壊れる
get_parent().get_parent().get_node("HUD/ScoreLabel").text = "100"
```

こういう `..` を辿るコードは、シーンを少し組み替えただけで全部壊れます。
正しい解決は **シグナル**（第6章）です。
「子は上に向かって『起きたよ』と叫ぶだけ、対応は親が決める」という形にします。
いまは「あの `get_parent().get_parent()` は良くないやつ」とだけ覚えておいてください。

## フォルダとファイルの決めごと

小さいうちは適当でも回りますが、あとで必ず効きます。最初に決めましょう。

```text
res://
├── scenes/     … .tscn を全部ここへ（player.tscn, enemy.tscn, main.tscn）
├── scripts/    … .gd を置く（シーンと同じ名前にすると探しやすい）
├── art/        … 画像
├── audio/      … 音
└── fonts/      … フォント
```

- **ファイル名は小文字とアンダースコアで**（`enemy_bullet.tscn`）。
  Web や Linux では大文字小文字が区別されるので、統一しておくと事故が減ります。
- **ノード名は大文字始まり**（`EnemyBullet`）。コードから `$EnemyBullet` と書くので、
  見た目で「ノードだな」と分かるようにしておきます。

## この章のまとめ

- **ノード**は単機能の部品。組み合わせてキャラや仕掛けを作る。全部入りの部品は無い。
- **親子**にすると、位置が連動し、まとめて消え、描画順が決まる（下ほど手前）。
- **シーン**はツリーを保存したファイル。画面も、キャラ1体も、弾1発もシーン。
- シーンは**インスタンス化**して何個でも置ける。元を直せば全部に反映される。
- 実行中の全体は **SceneTree**。`get_tree()` で触る。
- ノードを指すのは `$` と `%`。深い場所や動かす予定のものは `%` が安全。
- 生成は `preload` → `instantiate()` → `add_child()` の3手。削除は `queue_free()`。
- **迷ったらシーンを分ける。** 親をたどるコードは書かない。

次章は、いよいよコードです。**変数とは何か**というところから始めるので、
プログラミングが初めてでも置いていきません。
