# 第1章 ゲームエンジンとGodot

## そもそもゲームエンジンとは何なのか

「ゲームを作る」とき、実は本題に入る前にやることが山ほどあります。

画面にウィンドウを出す。そこに絵を描く。毎秒60回描き直す。キーボードが押されたのを知る。
音を鳴らす。2つの物体が重なったかを判定する。ゲームを配布できる形に固める。

これらは**どんなゲームでも共通**です。マリオでもテトリスでも要ります。
だったら毎回作り直すのは無駄なので、先人が作り置きしてくれた道具箱——それが
<Term>ゲームエンジン</Term>です。

<Statement kind="definition" title="ゲームエンジン">
ゲームに共通して必要な機能（描画・入力・音・物理・当たり判定・書き出し）をまとめた土台。
これを使うと、作り手は「このゲームならではの部分」だけを考えればよくなる。
Unity、Unreal Engine、GameMaker、そして Godot などがある。
</Statement>

料理でいえば、包丁もコンロも鍋も一式そろったキッチンです。
あなたがやるのは料理そのもの。キッチンの自作からは始めません。

## なぜ Godot なのか

エンジンはいくつもありますが、**最初の1本を完成させる**という目的なら Godot が有力です。

| | Godot | Unity | Unreal Engine |
| --- | --- | --- | --- |
| 値段 | 完全無料・売上の分配なし | 無料枠あり・条件付き | 無料・売上に応じて分配 |
| 容量 | 100〜200MBほど | 数GB〜 | 数十GB |
| 2Dの作りやすさ | とても得意 | 得意 | 3D寄り |
| 学習の入り口 | 概念が少なくて済む | 情報量は最大 | 重厚 |

とくに効くのが **容量と起動の速さ** です。
「やる気が出た瞬間に、10秒で起動して触れる」——これは学習の続きやすさに直結します。

もうひとつ。Godot は **エディタ自体が Godot 製** です。
つまりあなたがこれから触る画面は、Godot で作られたアプリケーション。
「このエンジンでちゃんとしたソフトが作れる」ことの一番の証拠になっています。

<Statement kind="remark" title="この記事が前提にするバージョン">
Godot **4系**（4.3 以降）を前提にします。執筆時点の安定版は 4.6 系です。
4.3 より前や、3系（3.5 など）とは書き方がかなり違うところがあるので、
古い記事を参考にするときは「Godot 4」と明記されたものを選んでください。
とくに `instance()` が `instantiate()` に、`Sprite` が `Sprite2D` に変わるなど、
名前が変わったものが多くあります。
</Statement>

## 手に入れて、起動する

### ダウンロード

公式サイト **godotengine.org** の Download から、自分のOS用のものを取ります。
ここで一度だけ迷うポイントがあります。

- **Godot Engine**（標準版）… GDScript でゲームを書く人向け。**こちらを選んでください。**
- **Godot Engine - .NET**（.NET版）… C# を使いたい人向け。追加のインストールが必要です。

この部では GDScript を使うので、標準版で構いません。
（C#が得意な人も、まずは標準版で概念をつかむのをおすすめします。
Godot の考え方を覚えるほうが先で、言語はあとから変えられます。）

### インストールは、しない

ダウンロードした zip を解凍すると、中に実行ファイルが1つだけ入っています。
**それをダブルクリックすれば起動します。** インストーラはありません。

好きな場所に置いて構いませんが、あとで探せるように
`ドキュメント/Godot/` のような分かりやすい場所に置くのがおすすめです。
Windows なら、実行ファイルを右クリックして「スタートメニューにピン留めする」と楽になります。

<Statement kind="remark" title="macOS で「開けません」と言われたら">
初回は Finder で実行ファイルを **右クリック → 開く** から起動してください。
ダブルクリックだと「開発元を検証できない」と止められることがあります。
</Statement>

## 最初のプロジェクトを作る

起動すると **プロジェクトマネージャ** が開きます。ここは「作品の一覧」です。
Godot では、1つのゲーム＝1つの<Term>プロジェクト</Term>＝1つのフォルダ、と対応します。

「作成」または「新規プロジェクト」を押すと、いくつか聞かれます。

- **プロジェクト名**：`hello-godot` など。あとから変えられます。
- **プロジェクトパス**：**空のフォルダ**を指定してください。「フォルダを作成」ボタンがあります。
  既存のファイルがあるフォルダを指定すると警告が出ます。
- **レンダラー**：`Forward+` / `Mobile` / `Compatibility` の3つ。

レンダラーは絵の描き方の方式です。迷ったら **Compatibility** を選んでください。

<Statement kind="remark" title="なぜ Compatibility を勧めるのか">
この部の最終目標は「ブラウザで遊べる形で公開する」ことです。
Web 書き出しやスペックの低いPCで確実に動くのは **Compatibility** です。
2Dゲームなら見た目の差はほぼありません。あとからプロジェクト設定で変更もできます。
</Statement>

「作成して編集」を押すと、エディタが開きます。ここからが本番です。

## エディタ画面の歩き方

初めて見ると圧倒されますが、覚えるべき場所は **5つ** だけです。
上から順に見ていきましょう。

```text
┌──────────────────────────────────────────────┐
│  ②メインの切り替え  [2D][3D][Script][AssetLib]  ▶実行 │
├────────────┬──────────────────┬────────────┤
│ ①シーンドック │                     │ ④インスペクタ │
│（部品の一覧）  │   ③ビューポート       │（選んだ部品の設定）│
│            │  （作業スペース）      │            │
├────────────┤                     │            │
│ ①ファイルシステム│                    │            │
│（プロジェクトの中身）│                  │            │
├────────────┴──────────────────┴────────────┤
│ ⑤下部パネル  [出力][デバッガ][オーディオ][アニメーション]  │
└──────────────────────────────────────────────┘
```

**① 左上：シーンドック**
いま編集している画面の「部品リスト」です。ツリー（枝分かれした一覧）で表示されます。
ゲーム作りの9割はここを触ります。第2章の主役です。

**① 左下：ファイルシステム**
プロジェクトフォルダの中身。画像・音・シーンファイル・スクリプトが並びます。
ここに表示されるパスの先頭 `res://` は「プロジェクトフォルダの中」という意味です。

**② 上中央：メインの切り替え**
`2D` `3D` `Script` `AssetLib` のタブ。作業に応じて切り替えます。
`Script` はコードを書く画面、`AssetLib` は素材や拡張のダウンロード場所です。

**③ 中央：ビューポート**
実際の作業スペース。ここで部品を配置します。
操作は「中ボタンドラッグで移動、ホイールで拡大縮小」。これだけ覚えれば足ります。

**④ 右：インスペクタ**
選んでいる部品の設定が全部出ます。位置、色、速さ、画像……。
「何かを変えたい」と思ったら、まずここを探すのが基本動作です。

**⑤ 下：下部パネル**
`出力` タブが最重要です。プログラムから出したメッセージや、
エラーの内容がここに出ます。**うまくいかないときは、まずここを見る。**

### 右上の実行ボタン

右上に再生ボタンのような並びがあります。左から順に、

| ボタン | ショートカット | 意味 |
| --- | --- | --- |
| プロジェクトを実行 | `F5` | メインシーンからゲームを起動 |
| 現在のシーンを実行 | `F6` | 編集中の画面だけを起動 |
| 停止 | `F8` | 実行中のゲームを止める |

制作中は **`F6`（今いじってる画面だけ試す）** を圧倒的によく使います。
覚えておくと作業が速くなります。

## 実際に何か表示してみる

説明ばかりでは退屈なので、5分で「動くもの」を作ります。

**1. 最初のノードを作る**
シーンドックに「ルートノードを生成」という選択肢が出ています。
`2Dシーン` をクリックしてください。`Node2D` という部品ができます。

**2. 文字を置く**
`Node2D` を選んだ状態で、シーンドック上部の **＋（子ノードを追加）** を押します。
検索欄に `Label` と打って、出てきた `Label` を選んで「作成」。

**3. 文字の中身を変える**
`Label` を選ぶと、右のインスペクタに `Text` という欄があります。
そこに `Hello, Godot!` と入力してください。ビューポートに文字が出ます。

**4. 保存する**
`Ctrl+S`（macOSは `Cmd+S`）。ファイル名を `main.tscn` にして保存します。
`.tscn` は「シーンファイル」の拡張子です。

**5. 実行する**
`F5` を押します。「メインシーンが定義されていません」と聞かれるので、
「選択」→ いま保存した `main.tscn` を選びます。
ウィンドウが開いて `Hello, Godot!` と表示されれば成功です。

<Statement kind="example" title="ここで起きたこと">
`Node2D` という入れ物に `Label` という部品を入れ、それを `main.tscn` という
ファイルに保存し、「ゲームを起動したらこのファイルから始める」と指定した。
Godot のゲーム作りは、突き詰めるとこの繰り返しです。
</Statement>

## 覚えておく用語（この章のまとめ表）

<Statement kind="definition" title="この章で出た言葉">

| 言葉 | 意味 |
| --- | --- |
| プロジェクト | ゲーム1本ぶんのフォルダ。`project.godot` が目印 |
| シーン | 画面や部品のかたまり。`.tscn` ファイル |
| ノード | シーンを構成する部品ひとつ。`Label` や `Node2D` など |
| ビューポート | 中央の作業スペース |
| インスペクタ | 選んだノードの設定を出す右のパネル |
| `res://` | プロジェクトフォルダの中を指すパスの書き方 |
| メインシーン | ゲーム起動時に最初に開かれるシーン |

</Statement>

## プロジェクトフォルダの中身

エクスプローラ（Finder）でプロジェクトフォルダを開くと、こうなっています。

```text
hello-godot/
├── .godot/          ← Godot が自動生成する作業用。触らない・共有しない
├── icon.svg         ← 新規プロジェクトに必ず入っている Godot ロゴの画像
├── main.tscn        ← さっき保存したシーン
└── project.godot    ← このフォルダがプロジェクトだという印＋設定
```

`.godot/` フォルダは、画像の変換結果などのキャッシュです。
消しても次回起動時に作り直されます。バックアップや共有からは外して構いません。

`icon.svg` は地味に重要です。**素材が何もなくても、とりあえずこれを絵として使えます。**
第7章で実際にこれをキャラクターにします。

## 最初に済ませておくとよい設定

メニューの **プロジェクト → プロジェクト設定** を開きます。
検索欄があるので、そこに単語を打って設定を探します。

- `表示 → ウィンドウ` の **ビューポートの幅 / 高さ**：ゲーム画面の基準サイズ。
  この部では横向きゲームで `1152 × 648`、縦向きゲームで `480 × 720` を使います。
- 同じ場所の **ストレッチ → モード** を `canvas_items`、**アスペクト** を `keep` に。
  こうしておくと、ウィンドウサイズを変えても画面全体が拡大縮小して破綻しません。

<Statement kind="remark" title="この2つだけは最初にやる価値がある">
ストレッチ設定を忘れると、他人のPCやスマホのブラウザで遊んでもらったときに
「画面の端が切れている」「UIがはみ出す」という事故が起きます。
プロジェクトを作った直後にやってしまうのが楽です。
</Statement>

## この章のまとめ

- **ゲームエンジン**は「どのゲームでも必要になる共通の道具箱」。自分で作らなくていい。
- Godot は無料・軽量・2Dが得意で、**最初の1本を完成させる**のに向いている。
- 導入は「zipを解凍して実行」だけ。インストール作業はない。
- レンダラーは **Compatibility** を選んでおくと、あとでWeb公開するときに困らない。
- エディタで覚える場所は5つ：**シーンドック / ファイルシステム / ビューポート / インスペクタ / 出力**。
- 困ったら **下部パネルの「出力」** を見る。これが今後ずっと効きます。

次章はいよいよ Godot の心臓部、**ノードとシーン**です。
ここを腹落ちさせると、あとの章が全部つながります。逆にここが曖昧なままだと、
「なんとなく動いたけど何をしたのか分からない」状態が続きます。じっくり行きましょう。
